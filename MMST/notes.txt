def get_exchange_rate(base_currency: str, target_currency: str) -> dict:
    """Looks up and returns the exchange rate between two currencies.

    Args:
        base_currency: The ISO 4217 currency code of the currency you
                       are converting from (e.g., "USD").
        target_currency: The ISO 4217 currency code of the currency you
                         are converting to (e.g., "EUR").

    Returns:
        Dictionary with status and rate information.
        Success: {"status": "success", "rate": 0.93}
        Error: {"status": "error", "error_message": "Unsupported currency pair"}
    """

    # Static data simulating a live exchange rate API
    # In production, this would call something like: requests.get("api.exchangerates.com")
    rate_database = {
        "usd": {
            "eur": 0.93,  # Euro
            "jpy": 157.50,  # Japanese Yen
            "inr": 83.58,  # Indian Rupee
        }
    }

    # Input validation and processing
    base = base_currency.lower()
    target = target_currency.lower()

    # Return structured result with status
    rate = rate_database.get(base, {}).get(target)
    if rate is not None:
        return {"status": "success", "rate": rate}
    else:
        return {
            "status": "error",
            "error_message": f"Unsupported currency pair: {base_currency}/{target_currency}",
        }

## Issue Summary: Qwen2.5-VL with vLLM + ADK does not execute tool calls

### Symptom

The RAG agent **never executes tools**, even though:

* `rag_agent.tools` contains 6 tools
* The model appears to “call” tools by outputting text like:

  ```
  _tracked_extract_keywords("query text")
  ```
* The worker explicitly reports:

  ```
  WARNING - No tool calls found in any events!
  ```

No tool wrapper logs (e.g. `[RAG Tools] retrieve_content: CALLED`) ever appear.

---

## What Is Actually Happening

1. **The model is NOT making real tool calls**

   * It is emitting **plain text** that *looks like* a function call
   * This text is placed in `message.content`, not in a structured `tool_calls` field

2. **vLLM never detects a tool call**

   * The vLLM tool-call parser does not recognize the model’s output as a valid tool invocation
   * Therefore:

     * `tool_calls = []`
     * ADK never executes any Python tools
     * The agent falls back to returning free-text answers

3. **ADK correctly registers tools, but never receives tool events**

   * Confirmed by logs:

     ```
     Agent has 6 tool(s) in tools attribute
     ```
   * But later:

     ```
     WARNING - No tool calls found in any events!
     ```

---

## Root Cause (Primary)

### ❌ Tool-call parser mismatch with model output format

The model is served as:

```bash
Qwen/Qwen2.5-VL-7B-Instruct
```

But vLLM is run with:

```bash
--tool-call-parser qwen3_xml
```

This causes a **format mismatch**:

* `qwen3_xml` expects **explicit XML-wrapped tool calls**, e.g.

  ```xml
  <tool_call>
  {"name":"tool_name","arguments":{...}}
  </tool_call>
  ```
* Qwen2.5-VL is **not being forced** (by prompt or template) to emit that format
* Instead, it emits:

  ```text
  _tracked_extract_keywords("...")
  ```

Because this does not match the parser’s expected syntax, vLLM:

* Treats it as normal text
* Does not populate `tool_calls`
* ADK never runs the tool

---

## Secondary Contributors

### 1. Tool calls are not strictly enforced in the prompt

* The instruction says “you MUST call tools”
* But does **not define the exact serialization format**
* LLMs default to “best-effort imitation” unless format is rigidly specified

### 2. Auto tool choice is enabled, but not sufficient

```bash
--enable-auto-tool-choice
```

* This only allows tool calling
* It does **not** force correct formatting
* The model can still choose to respond in plain text

### 3. ADK + LiteLLM expect structured tool calls

* They do **not** execute tools from strings in `content`
* Only structured `tool_calls` / `function_call` events trigger execution

  ```

  Rag_Agent > _tracked_extract_keywords("...")

* No wrapper logs like:

  ```

This definitively proves tools are **never executed**.

* ❌ Web search never executes
* ❌ The agent violates its own instruction (answers directly)
* ❌ RAG becomes a plain LLM responder

You must **either**:

  **or**

Tool calls must be:

* The **only output**
